# Frontend

Next.js app with the two faces of the product: the internal **backoffice** (advisors, admins, brokers, and partner users) and the mobile-first **buyer portal**. It is built on the Umbral design system (`../design`) and talks to the Django API through a client typed from the OpenAPI contract (`../contracts/openapi.json`).

The task that defines it, with every decision taken, is [`specs/TAREA-frontend-base.md`](../specs/TAREA-frontend-base.md).

## Technology Stack

| Piece         | Choice                                                               |
| ------------- | -------------------------------------------------------------------- |
| Framework     | Next.js 16 (App Router), React 19, TypeScript 5.9 (`strict`)         |
| UI            | Ant Design 6 (in the `antd` CSS layer) and Tailwind CSS 4 for layout |
| Design tokens | Imported from `../design/generated` (never copied)                   |
| Server data   | TanStack Query                                                       |
| Forms         | React Hook Form and Zod                                              |
| API client    | `openapi-typescript` (types) and `openapi-fetch`                     |
| Documents     | PDF.js (`pdfjs-dist`)                                                |
| Tests         | Vitest, Testing Library, and MSW                                     |
| Quality       | ESLint, Prettier, and `tsc --noEmit`                                 |

Versions are pinned exactly in `package.json`.

## Requirements

- Node.js 24 (`engines: >=24`).
- pnpm through corepack: run `corepack enable` once, and the `packageManager` field picks pnpm 12.18.0.
- The backend running for anything that calls the API. From `../backend`, `docker compose up -d postgres backend` starts PostgreSQL and the API at http://localhost:8000 (see [Demo and Frontend Development](../backend/README.md#demo-and-frontend-development)).

## Setup

```powershell
corepack enable
pnpm install
Copy-Item .env.example .env.local
pnpm dev
```

The app runs at http://localhost:3000. `.env.local` is never committed:

| Variable                                    | Default                                | Purpose                                                                                         |
| ------------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `API_ORIGIN`                                | `http://localhost:8000`                | Where Next.js forwards `/api/v1/*`. It is fixed at build time.                                  |
| `E2E_USER_EMAIL`, `E2E_USER_PASSWORD`       | —                                      | Internal test user for the end-to-end checks (see [Test User](../backend/README.md#test-user)). |
| `AUTH_ACCESS_COOKIE`, `AUTH_REFRESH_COOKIE` | both names, with and without `__Host-` | Session cookie names that `src/proxy.ts` looks for. Optional; comma-separated.                  |

## Commands

| Command                             | What it does                                                                    |
| ----------------------------------- | ------------------------------------------------------------------------------- |
| `pnpm dev`                          | Development server with hot reload (http://localhost:3000).                     |
| `pnpm build` / `pnpm start`         | Production build and server.                                                    |
| `pnpm lint`                         | ESLint (Next.js rules plus type-aware promise checks). Warnings do not fail it. |
| `pnpm format` / `pnpm format:check` | Prettier: write or check. Files use LF line endings.                            |
| `pnpm typecheck`                    | `next typegen` and `tsc --noEmit`.                                              |
| `pnpm test` / `pnpm test:watch`     | Vitest, once or in watch mode.                                                  |
| `pnpm test --coverage`              | Tests with coverage. CI requires 70 % of lines.                                 |
| `pnpm api:gen`                      | Regenerates `src/lib/api/schema.d.ts` from `../contracts/openapi.json`.         |

Before opening a pull request, the same checks as CI: `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test --coverage`, `pnpm api:gen` (no changes), and `pnpm build`.

## After an API Change

The contract is generated by the backend; the frontend never edits it. When the API changes:

1. Regenerate the contract from `../backend`, with the stack running:

   ```powershell
   docker compose exec backend python manage.py spectacular --settings config.settings.test --format openapi-json --file /contracts/openapi.json --validate --fail-on-warn
   ```

2. Regenerate the types here with `pnpm api:gen`, and commit both `contracts/openapi.json` and `src/lib/api/schema.d.ts`.

CI fails if `schema.d.ts` is out of date with the contract, also in a backend pull request that changes the contract (see [CI](#ci)).

## Key Conventions

- **Same origin.** `next.config.ts` forwards `/api/v1/*` to `API_ORIGIN`. The browser only talks to the frontend origin, so the session cookies live there and there is no CORS.
- **Every API call goes through `lib/api`**: `call(api.GET(...))` returns `{ data, version }` or throws `ApiError`. Writes send `X-CSRFToken`, and a `401` refreshes the session once (serialized across tabs). Dossier writes pass `If-Match` explicitly with the version from the `ETag`.
- **No business lists in the frontend.** Statuses, catalogs, and labels come from the API. `toneFor(kind, code)` only picks a color.
- **Menu and buttons by permission** (from `/auth/me`), never by role name.
- **Design tokens**, never hand-written colors: Tailwind classes such as `bg-bg-surface` and `text-text-secondary`, and the Ant Design theme from `../design/generated/antd-theme.ts`.
- **Write errors** show a toast by default (with the `request_id`). A form that handles its own errors sets `meta: { handlesErrors: true }` on the mutation and uses `applyFieldErrors`.

## Docker

The `frontend` service in `../backend/docker-compose.yml` builds `Dockerfile` from the repository root and serves the production build on port 3000. See [Demo and Frontend Development](../backend/README.md#demo-and-frontend-development).

## CI

[`../.github/workflows/frontend.yml`](../.github/workflows/frontend.yml) runs on every pull request. Its required check, `Frontend: lint, types and tests`, runs ESLint, Prettier, TypeScript, the tests, the coverage minimum (70 % of lines), the generated API types, and the build. It posts a single comment on the pull request (marker `<!-- ci-report:frontend -->`), built by `scripts/ci-report.ts`. When a pull request does not touch the frontend, the contract, or the design tokens, the job finishes green without checking anything and posts no comment.
