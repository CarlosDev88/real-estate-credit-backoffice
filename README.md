# Real Estate Credit Backoffice

[![Backend CI](https://github.com/CarlosDev88/real-estate-credit-backoffice/actions/workflows/backend.yml/badge.svg)](https://github.com/CarlosDev88/real-estate-credit-backoffice/actions/workflows/backend.yml)

MVP that manages Colombian real-estate credit applications. It has two faces: an internal operations backoffice and a buyer self-service portal, covering clients, opportunities, credit applications, documents, manual bank filings, and application tracking.

This repository is a monorepo: the Django API, the frontend, the API contract between them, the design system, and the functional documentation live together.

## Repository Structure

```text
/
├── backend/            # Django REST API (modular monolith, PostgreSQL)
├── frontend/           # Next.js app: backoffice and buyer portal (coming in specs/TAREA-frontend-base.md)
├── contracts/
│   └── openapi.json    # API contract generated by the backend; the frontend generates its types from it
├── design/             # Umbral design system: tokens and approved mockups
├── docs/               # Functional requirements, data model, and API specification
├── specs/              # Implementation tasks with their design decisions
└── .github/workflows/  # CI: backend.yml, with a PR report comment
```

## Quick Start (Backend)

Requirements: Docker Desktop running and Git. No local Python environment is needed.

```powershell
cd backend
Copy-Item .env.example .env
docker compose up -d --build
```

The API answers at http://localhost:8000 ([health](http://localhost:8000/health), [Swagger UI](http://localhost:8000/docs)). Configuration, services, commands, and module details are in [`backend/README.md`](backend/README.md).

This starts the **simple local mode**: only the `postgres` and `backend` containers (the frontend will add a third). Documents are stored on disk, the shared cache lives in PostgreSQL, and antivirus scans and filing packages run in the same process. Migrations are applied on every start. The project has no deployment; everything runs locally.

The real asynchronous architecture (Redis, SeaweedFS, a Celery worker, and ClamAV) is opt-in, with `docker compose --profile full up -d` and the "Full" block of `.env`. See [Local Modes](backend/README.md#local-modes) for both modes and what changes between them.

## API Contract

[`contracts/openapi.json`](contracts/openapi.json) is generated from the backend, and CI fails if it is out of date. Any pull request that changes the API must include the regenerated contract; see [OpenAPI Contract](backend/README.md#openapi-contract) for the command.

## CI

Every pull request runs the backend checks in [`backend.yml`](.github/workflows/backend.yml). The `Lint, types and tests` job is the required check: it fails if any check fails, and pytest warnings never block it. A single comment on the pull request, updated on every push, shows the status of each check and the details of what failed:

![CI report comment on a pull request](docs/images/ci-report.png)

[CI Report](backend/README.md#ci-report) explains what each status means and how to preview the report locally.
